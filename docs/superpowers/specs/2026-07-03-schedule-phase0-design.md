# Интерактивное расписание (Фаза 0) — дизайн

> Пересборка `SCHEDULE_PLAN.md` под **расширенную модель группы** из `TELEGRAM_BOOKING_SPEC.md` (Фаза 0). Отображение — по референсу `savva_team_schedule3 (1).html`. Документ фиксирует **решения**; пошаговый план реализации — отдельным файлом (writing-plans).

## Цель

Заменить захардкоженное расписание на лендинге интерактивной сеткой «время × N дней», настраиваемой из админки. Каждая ячейка-группа несёт скрытые поля допуска (уровень/аудитория/пол/тренер/вместимость) — задел под запись на группы (Фаза 2). Клик по карточке ведёт к форме записи с предзаполнением.

## Архитектура

- Единый источник — JSON-ключ `content.schedule_data` (таблица `content`, SQLite). Никакого дублирования.
- Лендинг читает через существующий `GET /api/content`, строит сетку в JS.
- Админка редактирует и сохраняет через существующий `POST /api/content` (`upsertContent` уже принимает произвольные пары ключ→значение — **серверный код для сохранения не нужен**).
- Новых эндпоинтов и таблиц БД **нет**.
- Стек: Express + better-sqlite3 (сервер), ванильный HTML/CSS/JS (лендинг и админка), ES-модули.

## Решения (из брейншторма)

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Модель ячейки | **Расширенная Фаза 0**: `id`, `title`, `meta`, `cat` + поля допуска |
| 2 | `coach_id` без таблицы `coaches` | **Слот-строка** `"coach1"\|"coach2"\|"coach3"\|""`; имя берётся из `coachN_name` контента. Миграция на таблицу `coaches` (Фаза 1) тривиальна |
| 3 | Поля допуска на витрине | **Скрытые метаданные**. Витрина показывает только `title`+`meta`+цвет по `cat` (как референс). Поля допуска подхватит Фаза 2 |
| 4 | Дни недели | **Конфигурируемый массив `days`**, сид = 5 будних (ПН–ПТ, как референс). Админ может добавить/убрать день |
| 5 | Стабильный `id` | Генерится **в браузере (админка)** при первом заполнении ячейки: `'g_' + Date.now().toString(36) + rand`. Стабилен при последующих правках → брони Фазы 2 не рвутся |
| 6 | Раскладка admin-ячейки | **Компактная**: `title`/`meta`/`cat` видны сразу; блок допуска (уровень/аудитория/пол/тренер/вместимость) — в **сворачиваемой** части ячейки |
| 7 | Отображение витрины | По референсу `savva_team_schedule3 (1).html` (цвета, скругления, свечение `extreme`, мобильная раскладка) |

## Модель данных `schedule_data`

JSON-строка:

```json
{
  "days": ["ПН","ВТ","СР","ЧТ","ПТ"],
  "rows": [
    {
      "time": "9:30–11:00",
      "cells": [ <cell|null>, <cell|null>, <cell|null>, <cell|null>, <cell|null> ]
    }
  ]
}
```

Ячейка:

```json
{
  "id": "g_lx9f2a",
  "title": "Девушки 1,5–2",
  "meta": "Beginner / Light",
  "cat": "women",
  "level_min": 1.5,
  "level_max": 2.0,
  "audience": "adult",
  "gender": "f",
  "coach_id": "coach2",
  "capacity": 8
}
```

Правила:
- `days` — произвольной длины (сид = 5). Для каждой строки `cells.length === days.length` (индекс ячейки = индекс дня).
- Ячейка = объект или `null`. Пустой `title` трактуется как пустая ячейка (на витрине — невидимый плейсхолдер, сохраняющий сетку на десктопе; на мобилке скрыт).
- `cat` ∈ `women | men | kids | mixed | extreme` — **только цвет/оформление**.
- `id` — стабильный идентификатор группы, генерится в админке при первом заполнении, при правках не меняется.
- Поля допуска (`level_min`, `level_max`, `audience`, `gender`, `coach_id`, `capacity`) — метаданные для Фазы 2, на витрине не рендерятся.
- Значения по умолчанию для новой заполненной ячейки: `cat:'mixed'`, `level_min:1`, `level_max:7`, `audience:'adult'`, `gender:'mixed'`, `coach_id:''`, `capacity:8`.
- Легенда на витрине строится автоматически из множества `cat`, реально встречающихся в данных.

## Поведение на лендинге (витрина)

Стили и разметка — адаптация `savva_team_schedule3 (1).html` под CSS-переменные лендинга (`--bg2`, `--surface`, `--border`, `--text`, `--muted`, `--accent`; тёплый акцент `--sch-warm: #FFB347` локально).

- Сетка: колонка времени (110px) + `repeat(days.length, minmax(180px, 1fr))`, `gap` 14px. Горизонтальный скролл на узких десктоп-экранах.
- Заголовки дней сверху; строки со временем слева.
- Карточка: цветная левая полоска по `cat`, `title` (крупно, uppercase), `meta` (мелко, uppercase). Hover — подъём и подсветка рамки. `extreme` — рамка/свечение.
- Карточка показывает **только** `title` + `meta` + цвет. Поля допуска не выводятся.
- Категории → цвета: `women`/`mixed` — `--accent`; `men` — `--sch-warm`; `kids` — градиент `--accent`→`--sch-warm`; `extreme` — `--accent` + свечение.
- **Мобилка (≤760px):** грид → вертикальный блок; для каждого дня заголовок `.mobile-day`, под ним карточки этого дня; пустые ячейки и десктоп-хедеры/тайм-колонка скрыты. (Строится тем же JS-рендером — генерируем и десктоп-грид, и мобильный список, переключение через CSS media-query.)
- **Клик по карточке** → плавный скролл к `#contact` + подстановка в `#contactComment` строки `Запись: {title} · {ДЕНЬ} {time}`. (Доп. фича к референсу; не мешает витрине.)
- Битый/отсутствующий `schedule_data` → рендер тихо выходит, без исключений.

## Поведение в админке

Новый пункт меню **«Расписание»** между «Программы» и «Цены».

- Редактор-таблица: строки со временем; кнопки «+ Строка» / «Удалить строку»; управление днями — «+ День» / «− День» (добавляет/убирает последний день, синхронно расширяя/усекая `cells` во всех строках).
- Ячейка (компактная раскладка):
  - Всегда видно: *Название*, *Meta*, *Категория* (dropdown с «— пусто —»).
  - Сворачиваемый блок допуска (toggle «Допуск ▾»): *Уровень от* / *Уровень до* (числа 1–7), *Аудитория* (adult/kids), *Пол* (m/f/mixed), *Тренер* (dropdown: «—» + `coach1/2/3` с именами из `coachN_name`), *Вместимость* (число).
- **«Сохранить и опубликовать»** → `POST /api/content` с `{schedule_data: JSON.stringify(...)}`; toast. При сборе данных новым заполненным ячейкам присваивается стабильный `id`.
- Данные редактора грузятся из `/api/content` (мерж в `state.schedule`), при отсутствии — из встроенного дефолта.

## Сервер

Добавить ключ `schedule_data` в `CONTENT_DEFAULTS` — сид расширенными ячейками на основе данных референса (Девушки, Мужчины 2,5–3,5, Экстремалы 3,5+, Дети 5–7/7–11/11–16, Смешанные). `POST /api/content` уже поддерживает произвольные ключи — иного серверного кода не требуется.

## Связь с последующими фазами

- `coach_id` = слот `coachN` → в Фазе 1 мапится на записи таблицы `coaches` один-в-один.
- Стабильный `id` ячейки = идентификатор группы для `bookings` (Фаза 2).
- Поля допуска = вход для правила допуска в группу (Фаза 2): `audience==audience AND level_min<=level<=level_max AND (gender=='mixed' OR gender==student.gender)`.
