# Фаза 3A — Доступность тренеров — дизайн

> Первый под-этап Фазы 3 (`TELEGRAM_BOOKING_SPEC.md`). 3A даёт модель и админ-редактор недельных окон свободного времени тренера. **Нарезки слотов, индивидуальной брони, изменений Mini App — нет** (3B).

## Цель

Тренер (через админку) задаёт недельный шаблон свободных окон (`день × from–to`) на каждого тренера. Эти окна — источник для нарезки на слоты и индивидуальной брони в 3B.

## Архитектура

- Расширяем `server.js`: таблица `coach_availability` + prepared statements + admin API `GET /api/availability`, `POST /api/availability`.
- Расширяем `public/admin.html`: раздел «Доступность» — выбор тренера + недельная сетка окон.
- Стек: Express + better-sqlite3. Тест-фреймворка нет — ручная проверка (curl / браузер). Часовой пояс — серверный localtime.

## Решения (из брейншторма)

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Схема | Таблица `coach_availability(slot, day, from_time, to_time)`, несколько окон на день |
| 2 | `day` | Число 0–6 (0=Вс…6=Сб, JS getDay — единообразно с `WEEKDAY` из 2B); в UI метки ПН–ВС |
| 3 | Время | `from_time`/`to_time` текстом `HH:MM` |
| 4 | Дней | 7 (ПН–ВС); индивидуальная тренировка возможна в любой день |
| 5 | Сохранение | Замена всех окон тренера целиком (delete+insert в транзакции) |
| 6 | Автовычет групп | Нет (граница спеки) — тренер ведёт окна вручную |
| 7 | Шаг слота / длительность (параметр для 3B) | **Шаг сетки слотов 30 минут; минимальная тренировка 60 минут.** Фиксированный час vs выбираемая длительность ≥1ч (кратно 30) — открытый вопрос 3B |

## Данные — `coach_availability`

```sql
CREATE TABLE IF NOT EXISTS coach_availability (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  slot      TEXT NOT NULL,      -- coach1|coach2|coach3
  day       INTEGER NOT NULL,   -- 0=Вс … 6=Сб (JS getDay)
  from_time TEXT NOT NULL,      -- 'HH:MM'
  to_time   TEXT NOT NULL       -- 'HH:MM'
);
```
Несколько строк на `(slot, day)` = несколько окон в день. Пустой набор строк = тренер недоступен. Индексы не обязательны (объём мал); при желании — `CREATE INDEX ON coach_availability(slot)`.

## API (админ, `requireSecret`)

### `GET /api/availability?slot=coachN`
- `slot` обязателен и должен существовать (иначе 400).
- Ответ: `[{ id, day, from_time, to_time }]`, сорт по `day`, затем `from_time`.

### `POST /api/availability`
- Тело: `{ slot, windows: [{ day, from_time, to_time }] }`.
- Валидация: `slot` существует (иначе 404); каждый window — `day` целое 0–6, `from_time`/`to_time` формата `HH:MM` (00:00–23:59), `from_time < to_time`; любое нарушение → 400 (вся операция отклоняется).
- Действие: в транзакции `DELETE FROM coach_availability WHERE slot=?` затем `INSERT` каждого валидного окна. Пустой `windows` → просто очистка окон тренера.
- Ответ: `{ ok: true, count }`.

## Админка — раздел «Доступность»

- Новый пункт меню «Доступность» (рядом с «Расписание»/«Записи»).
- **Выбор тренера:** кнопки/переключатель по 3 слотам (`coach1/2/3`) с именами из контента (`state.texts.coachN_name` или `GET /api/coaches`).
- При выборе тренера — `GET /api/availability?slot=coachN` → недельная сетка:
  - 7 строк-дней (ПН…ВС; порядок ПН-первый, но `day` хранит 0–6).
  - У каждого дня — список окон: два инпута времени (`from`/`to`) + кнопка «✕» удалить; кнопка «+ окно» добавляет пустое окно (по умолчанию `10:00–11:00`).
- **«Сохранить»** → собрать все окна (пропуская пустые/невалидные с подсветкой) → `POST /api/availability` → toast «Доступность сохранена».
- Пустое состояние дня — «нет окон».

## Ошибки/безопасность

- Все эндпоинты под `requireSecret`. Невалидное окно (`from ≥ to`, плохой формат, day вне 0–6) → 400, ничего не сохраняется (атомарная замена). Неизвестный slot → 404/400.

## Тестирование (ручное, curl/браузер)

- `POST /api/availability` с двумя окнами (напр. `coach1`, day=1 `10:00–13:00` и `18:00–21:00`) → `{ok:true, count:2}`; `GET` возвращает их сортированными.
- Повторный `POST` меньшим набором → старые заменены (не накапливаются).
- Валидация: `from_time >= to_time` → 400; `day=9` → 400; плохой формат `25:00` → 400; неизвестный slot → 404.
- Пустой `windows` → очистка (GET пусто).
- Админка: выбор тренера грузит окна; добавление/удаление/сохранение работает; после перезагрузки окна на месте (грузятся с сервера, без персиста в state — как исправлено для chat_id в 2C).

## Границы (3A, YAGNI)

Нет: нарезки окон на слоты (30-мин шаг, ≥60 мин) и индивидуальной брони (3B); изменений Mini App (3B); автовычета групповых занятий из окон; учёта отпусков/исключений на конкретную дату (только недельный шаблон).

## Связь с 3B

- `coach_availability` (недельный шаблон) → 3B нарезает на кандидаты-слоты (шаг 30 мин, длительность ≥60 мин) на 2 недели, вычитает занятые `bookings type='individual'` для тренера, показывает свободное время; бронь `type='individual'` с `coach_id` (slot) + `datetime`. Уведомление/отмена — механизмы 2C. Индивидуальные в разделе «Записи».
- Открытый вопрос 3B: фиксированная длительность 60 мин vs выбираемая ≥60 (кратно 30).
